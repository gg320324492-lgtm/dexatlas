# v1.2.0 — 桌面应用自包含与界面说实话

**日期：** 2026-11-27 · **tag：** `v1.2.0` · **上一版本：** [v1.1.0](v1.1.0.md)（2026-11-25）

v1.2.0 交付 Phase 5 的全部工程内容：**桌面应用自包含**（后端随应用启动，
不再要求用户自己起服务）、**阶段级进度契约**（后端把五个推进点记成事实），
以及一批「界面说实话」的修复——分析进行中不再谎称「后端未安装」，分析**结束**
之后不再谎称「版本探测中」，跑失败的分析必须落库，前端的时间模拟删除，
窄栏里的标题不再竖排，键盘用户不再被按钮夺走焦点。

自 v1.1.0 起 main 共 73 个提交，经 21 个 PR 逐一评审合并。

## What's new

### 桌面应用自包含（Phase 5 W1 / W2）

- **侧车进程**：Tauri 壳启动时按配置拉起现有 DexAtlas 后端（默认
  `python -m dexatlas.workbench`，强制 `--port 0` 由系统分配端口），从后端
  输出抓取实际端口注入前端；侧车退出或崩溃时页面如实显示错误，不造数据；
  设置页可改后端命令并重启。
- **强杀宿主不留孤儿后端**：Windows **作业对象**兜底——后端挂起创建 → 加入
  作业 → 恢复主线程，于是它自己拉出来的后代也继承作业身份；宿主一死，系统
  关闭作业句柄，整棵进程树随之终止。**这一层进了 CI 门禁**（`cargo test --lib`，
  只跑在 Windows 上）——此前 24 个 Rust 测试没有任何门禁在跑。
- **阶段级进度契约**：pipeline 在 `inspect` → `parse-apktool` →
  `index-androguard` → `decompile-jadx` → `publish` 五个推进点记录阶段事件，
  新增只读端点 `GET /api/projects/{id}/runs/{run_id}/stages`（REST 与 workbench
  同形状）。既有 run 对象字段集不变，纯新增。

### 界面说实话

- **前端时间模拟删除**（PR #23）：拿不到后端事实时如实说「状态未知」，不再
  按时间编一条看起来像事实的进度条。
- **失败的分析必须落库**（PR #26）：管线算出 `FAILED` 却只在 `COMPLETED` 时
  调 `publish_run`——失败状态从来没落库，项目行留在 `running`，界面在分析结束
  **4 分 44 秒**后仍显示「分析中」。
- **分析进行中不再谎称「后端未安装」**（PR #30）：那一轮 run 的
  `tool_versions` 在版本探测完成前没有落库，键不存在，前端把「键不存在」与
  「值是 null」当成同一件事。
- **分析结束后不再谎称「版本探测中」**（PR #33）：`null` 有两种完全不同的
  意思——「还没探测出来」与「压根没装」——run 的记录分不开。现在机器那份名单
  （`GET /api/backends`）与 run 的记录一起判，两种说法各归各的事实。
- **阶段格与后端推进点一一对应**（PR #32）：「解析」格拆成「解析」与「反编译」
  两格，「证据」格去掉（证据仍然产出，只是不再占一格说自己没有对应阶段的
  进度）。格上的状态**就是后端报的事实**，角标也不必再解释「哪一格是推断值」。
- **窄栏里的卡片标题不再被角标挤成竖排**（PR #31）。
- **不可用的按钮不夺走焦点**（PR #33）：取消按钮在取消进行中改用
  `aria-disabled`，键盘用户不会被扔回页面开头。

### 验收与真机复验

- **打包 exe 的完整后端配置**：JADX + Apktool + Androguard 齐全时跑出
  12 条证据、`complete: true`；MSI 安装路径 `msiexec /i … /passive` 退出码 0，
  装完能启动能分析（`/qn` 装不上——静默模式下 Windows Installer 不做凭据
  提升，是机制问题不是包的毛病）。
- **失败与取消两条时间线真机走通**：「取消」这条路径确实存在（红色取消按钮 →
  确认 → `POST /cancel` → 管线在下一个检查点才停 → run 记 cancelled、项目记
  failed、未发布任何结果）。**取消发生在别的阶段**（索引期、反编译期）也各自
  走过一遍，用后端自己的阶段事件端点判定「目标阶段正在跑」才点取消，不靠盯
  界面猜。
- **未完成目标的清单**：把散在验收报告、走查报告、补测报告、状态页与运营
  清单里的未完成项收成一处，分四类归口。

逐条证据与截图见[失败/取消走查报告](../reports/phase5-failure-timeline.md)、
[真机补测报告](../reports/phase5-machine-verification.md)与
[Phase 5 验收报告](../reports/phase5-acceptance.md)。

## Verification

- 套件：**1887** 个测试（**1738** 快 + **149** 集成），**1886 passed, 1 skipped,
  0 xfailed**，覆盖率 **93.4%**（**7485**/**8018** 行），由 `scripts/refresh-report-figures.py`
  对发布树完整测量生成（后端环境变量、fixtures、Pillow、ffmpeg 齐备，无 skip
  掩盖）。那一条 skip 是 POSIX 版的 launcher 测试，在 Windows 上按设计跳过
  （Windows 版在它上面那条）。
- 门禁：ruff lint + format、mypy strict、vulture、check-doc-citations、
  check-version-claims、check-release-numbers、make-social-preview 全部通过。
- 桌面应用：`npm run build` 零错误；vitest **70** 例全绿；Tauri release 真机
  全链路实测（上传 → 证据 → 导出）。

## What this release does not claim

- 桌面应用第一验收平台是 Windows；macOS/Linux 未验证。
- 未做应用商店分发、自动更新服务与签名证书；安装包仅为本机构建产物，
  **本次发布不附带安装包**。
- 真实第三方 APK（加固、大型多 dex）与 MSI 的升级 / 卸载 / repair 路径
  **未测**——需要外部样本或别的机器，已记在未完成目标清单的 D 类。
- 取消对话框上的 **Esc** 键**未验到**：那个确认框不是独立窗口（是 WebView2
  在自己窗口里画的），没有窗口可递键盘，CDP 也只有「替用户回答」的接口。
  能验的是浏览器自己的两个回答：「取消」→ 分析继续跑、「确定」→ 发出取消请求。
- 桌面应用通过本地 HTTP 调用既有分析核心，不引入新的分析能力。
