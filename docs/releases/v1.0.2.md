# DexAtlas v1.0.2 — Phase 4 收尾、依赖加固与测量对齐

v1.0.2 closes Phase 4 and puts DexAtlas into Portfolio Freeze. It does not add a
new analysis backend, a new rule engine or a new public contract. It fixes
document statements that had drifted from the code, completes the M15 evidence
chain, hardens the dependency and release pipeline, and records a fresh full
measurement of the tagged tree. The boundary is the same as before: DexAtlas is
static, evidence-first Android analysis; an agent answer is a lead to verify,
never a finding.

## What's in this release

- **Phase 4 M11–M15 is complete.** The baseline, UI design, Workbench
  implementation, accessibility work and release materials are recorded in
  [`docs/roadmap/phase4-plan.md`](../roadmap/phase4-plan.md) and the reports it
  links. The project now follows the Portfolio Freeze rules in
  [`docs/portfolio/freeze.md`](../portfolio/freeze.md).
- **Document claims match the implementation.** The MCP `source` tool's
  `limit` bound, Androguard worker isolation, `DEXATLAS_LOG_LEVEL`, the current
  version number and the bilingual README demo entry now say what the code and
  committed assets actually provide. The M15 review record no longer points at
  screenshot frames that were never committed, and the release plan records
  which of its steps have since landed.
- **Outward text matches the evidence.** The bilingual README now links the
  recorded 91-second demo and the 233-second technical walkthrough, and the
  model-comparison wording reports each round separately. The v1.0.1 release
  body was corrected so its CI run is described as an ancestor of the tag tree
  rather than as a run on that exact tree.
- **Dependency and release hardening.** The Dockerfile pins the uv image by
  digest; backend and fixture download scripts verify sha256; all GitHub
  Actions references are pinned to commit SHAs.
- **A fresh full measurement.** The execution report was regenerated from the
  complete environment after the version bump. Its documented numbers are
  1808 tests (1659 fast + 149 integration), 1807 passed, 1 skipped,
  0 xfailed, and 93.3% first-party coverage (7323/7852 lines). The report
  carries the source fingerprint of the tree this release ships.

## What this release does not claim

- No new backend, vulnerability rule, authenticated service, multi-tenant
  deployment or distributed queue was added in Phase 4.
- No REST, MCP, CLI, report schema, evidence locator, status code or exit code
  contract was changed.
- The only intentional skip in the full run is the POSIX launcher test on
  Windows; the Windows counterpart passes. A skip is not counted as a pass.
- The release body of v1.0.1 was corrected for wording, not replaced with a new
  measurement of that old tag.

## Verification

The push that prepared this release ran the full GitHub Actions set: 13 checks
passed and the tag-only measurement comparison was skipped by design, as it is
on every push. Locally, the full measurement, ruff format and lint, mypy strict,
vulture, the citation checker, the version-claim checker, the release-number
checker, the social-preview check and `git diff --check` all pass on the
released tree.

The report is the authority for every number above:
[`docs/reports/phase1-execution-report.md`](../reports/phase1-execution-report.md).
The release record keeps the generated figures rather than restating them by
hand; the measurement script and the source fingerprint tie them to this tree.
