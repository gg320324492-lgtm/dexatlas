# DexAtlas v0.1.0 — Functional Foundation

**From APK to Evidence.** An evidence-first Android reverse engineering and analysis
platform. This release is the Phase 1 foundation: a complete static analysis pipeline
that works with every language model switched off.

---

## What this release is

One command analyses an APK and produces a report where **every claim points at a code
location**:

```bash
uv run dexatlas analyze examples/demo-app/demo.apk --output report.md
```

```text
✓ apk_12cdaf61adea0d1a — 5 classes, 8 methods, 23 cross-references (2.6s)
```

The output above is a real run against the bundled demo application. The full session —
backend discovery, exported components, code search, cross-references, decompiled
source, and the report — is recorded in the README.

## What is implemented

- **APK ingestion** — ZIP and Android-marker validation, streamed SHA-256 content
  addressing, DEX / native library / signature inspection
- **Three backends as subprocess adapters**, never linked or vendored:
  - **JADX** — Java decompilation, method body extraction
  - **Apktool** — `AndroidManifest.xml`, resources, and Smali as the fallback when
    decompilation fails
  - **Androguard** — the DEX symbol index, with cross-references recovered by walking
    bytecode
- **Evidence levels** — `verified` / `lead` / `insufficient`. The level is passed
  explicitly by the caller and never inferred from wording, so a model claim that says
  "CONFIRMED VULNERABILITY" still cannot be promoted to a finding
- **Provenance on everything** — source tool, tool version, APK hash, code location
- **SQLite + FTS5** — full-text search over indexed symbols
- **CLI and REST API over one analysis core** — they cannot drift apart, because
  neither contains analysis logic
- **JSON and Markdown reports**, with backend errors surfaced rather than omitted

## Try it

```bash
git clone https://github.com/gg320324492-lgtm/dexatlas.git
cd dexatlas
uv sync --extra analysis
uv run dexatlas analyze examples/demo-app/demo.apk -o report.md
```

No APK needs to be downloaded: `examples/demo-app/demo.apk` is built from the smali
sources committed beside it, and `scripts/build-demo-apk.sh` rebuilds it.

Full instructions: **[docs/install.md](https://github.com/gg320324492-lgtm/dexatlas/blob/main/docs/install.md)**

## Known limitations

Stated up front, because a tool that hides its blind spots is worse than one that does
not.

- **Decompilation is not complete, and no decompiler's is.** JADX fails on heavily
  obfuscated control flow. Where it does, the method is marked `decompiled=False` and
  DexAtlas falls back to Smali rather than reporting nothing.
- **Cross-references come from bytecode**, which means an `invoke` on an inherited
  method names the subclass rather than the declaring class. This is how the DEX
  encodes it, not a DexAtlas choice.
- **Analysis is bounded.** Method, string and instruction limits protect against
  pathological obfuscated APKs; hitting one is logged, and the report is truncated rather
  than silently short.
- **This release has no AI in it.** No agent orchestration, no MCP server, no web
  workbench. Those are Phase 2 and they are not here. What is here is the substrate they
  will use.
- **The REST API's upload runs analysis in a background task**, which is honest about
  being single-process rather than pretending to scale. Phase 3 introduces a real queue.
- **JADX resolution on Windows** requires either the platform launcher or
  `DEXATLAS_JADX_PATH` pointing at `jadx.bat`. The extensionless `jadx` in the
  distribution is a shell script and will not execute there.

## Quality

- 204 tests, **88% coverage** on first-party code
- `mypy` strict, `ruff` lint and format — clean
- GitHub Actions green on Python 3.12 and 3.13: lint, tests, coverage gate, Docker
  image build (which verifies the backends actually run), dependency audit
- The test suite passes both **with** and **without** analysis backends installed, so the
  degradation path is tested rather than assumed
