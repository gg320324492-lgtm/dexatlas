# DexAtlas v0.1.2 — The Acceptance Checklist, Actually Met

**Five test APKs, built by this project, and a demo video.** v0.1.2 delivers the
items the Phase 1 acceptance checklist asked for — and corrects how that checklist
had been recorded.

---

## What changed

### Five self-built test APKs

The Phase 1 plan asks for **five test APKs built by this project**, each verifying
the import and index pipeline. There was one. There are now five, and they are not
interchangeable — a single sample would let a pipeline that handles one layout look
like a pipeline that handles them all.

| Sample | What it covers |
|---|---|
| `demo-app` | The general case: components, permissions, cross-references |
| `multidex-app` | Two dexes, so `smali/` and `smali_classes2/` both exist, and one class name appears in both so resolution can be checked for determinism |
| `obfuscated-app` | One-letter packages, classes and methods, no source hints |
| `strings-app` | Mostly string constants, for the search index |
| `wide-app` | An interface with two implementations and a factory, for the cross-reference index |

Every class in every one of them is the smali committed beside it.
`scripts/build-test-apks.sh` rebuilds all five, and rebuilding from a fresh clone
reproduces the committed bytes exactly. None of them is a mystery binary.

### A demo video

`docs/assets/demo.mp4` — encoded from the same frames as the README's GIFs, rather
than recorded a second time, so the two cannot drift apart.

### The checklist, in the plan's own words

The exit checklist in `docs/roadmap/ROADMAP.md` had been paraphrased into something
easier to tick. The plan asks for "five **self-built** test APKs" and a "demo
**video**"; the checklist said "verified against test APKs" and "a generated demo
recording", and every box was ticked.

One self-built sample and a GIF are not five samples and a video. The wording was
doing the work the items were supposed to do.

This mattered beyond the paperwork. Phase 1 was marked shipped, v0.1.0 was released
with notes claiming the checklist passed, and the gap was listed as "honestly
disclosed" in the execution report. Disclosing a gap is not the same as closing it.
The project exists on the principle that a conclusion you cannot point back to is
not a conclusion — and the claim that Phase 1 was complete could not be traced to the
five samples' results, because those results had never been produced.

### Three tests so it cannot happen again

The problem was never a missing test. "Is Phase 1 actually done?" is not a question
you can assert on — it is a checklist, and nothing kept the checklist and the facts
it referred to in step. So the checklist itself is now verified:

- Every APK committed to the repository must have its smali sources beside it
- The build script's sample list must match what is actually on disk
- The set of APKs allowed in the repository is derived from the filesystem, not
  written out by hand

The last one is the important one. A hand-written allow-list is exactly where a
paraphrase would slip in again.

## Verification

| Configuration | Result |
|---------------|--------|
| All backends installed | 274 passed, 1 xfailed |
| Apktool only, JADX absent | 274 passed, 1 xfailed |
| No backends installed | 238 passed, 36 skipped, 1 xfailed |

First-party coverage is **89.2%** (1525/1709 lines). `mypy` strict and `ruff` lint
and format are clean. GitHub Actions is green on Python 3.12 and 3.13.

The samples were checked the way a stranger would meet them: cloned from GitHub,
rebuilt from their smali sources, and analysed. The rebuild reproduced the committed
bytes exactly, and the full suite passed in the clone.

## Known limitations

Stated up front, because a tool that hides its blind spots is worse than one that
does not.

- **The samples are small** — the largest is under 3 KB with five classes. The
  *layouts* are covered; the *scale* is not. There is no large-APK data point, so
  index performance and the instruction limits have never been under real load.
- **The obfuscated sample is hand-written** obfuscation, short names and no source
  hints. It is not a realistically hardened APK with control-flow obfuscation.
- **An empty backend path does not disable that backend**, although `settings.py`
  documents that it should. This predates v0.1.1 and is recorded as a strict `xfail`
  test, so the day it is fixed the test fails and the marker has to be removed.

The full list, with the decisions behind them, is in
[the execution report](https://github.com/gg320324492-lgtm/dexatlas/blob/main/docs/reports/phase1-execution-report.md).
