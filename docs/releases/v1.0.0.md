# DexAtlas v1.0.0 — The Evidence-First Portfolio Milestone

DexAtlas v1.0.0 is Phase 3's portfolio-and-delivery milestone: the claims
baseline re-verified against the code (M5), a frozen 20-question service
regression set for the agent with honest level-2 results (M6), client-ready
deliverables — offline HTML reports, minimal evidence packages and rewritten
case studies with their attachments on disk (M7), the public contract table,
workspace-wide `--workspace` and a new exit code for runs that indexed nothing
(M8), and a bilingual README showcase (M9). It is for a reviewer, a client or
an agent that needs Android static analysis whose every number traces back to
the bytes it came from. The boundary is one sentence: this is static,
evidence-first analysis, and the agent inside it is bounded — its answers are
leads to verify, never verified findings.

## What's in this release

- **M5 — claims baseline.** Every outward claim re-checked against the code
  and committed traces; the three benchmarks regenerate byte-for-byte from
  their traces. [phase3-baseline.md](../reports/phase3-baseline.md)
- **M6 — frozen service regression set (20 questions).** Level-0
  deterministic scoring is 20/20 with no model in the loop; the level-1
  scripted drill proves the pipeline end to end. The level-2 real-model batch
  (MiniMax-M3.1-Flash, three independent rounds) scored **24/60 = 40.0%
  (45%/40%/35% per round) against the acceptance bar of ≥16/20 per round and
  ≥54/60 (≥90%) over three rounds — not passed**
  ([m6-level2-real.md](../benchmarks/m6-level2-real.md)). After the
  execution-layer fixes (four) and the C2 single-word fallback, the full
  three-round retest on the complete 20-question denominator scored
  **49/60 = 81.7%
  (15/16/18 per round; r2 and r3 met the per-round ≥16/20 line, r1 did
  not)** — still below the three-round ≥90% bar (A 21/60, B 21/60; traces
  1,182,356 tokens)
  ([m6-level2-retest4.md](../benchmarks/m6-level2-retest4.md); the
  single-round retest that first met the per-round line is recorded in
  [m6-level2-retest2.md](../benchmarks/m6-level2-retest2.md)). Two further
  narrow verification rounds over the six known failure surfaces (6 questions
  × 3 rounds × 3 configurations each) also stayed below the narrow gate, which
  is **≥4/6 converted** and **≥3/5 on the deterministic subset** — a second
  line of its own, not the level-2 bar above (≥16/20 per round, ≥54/60 over
  three rounds): round 2 converted **2/6** (deterministic 2/5)
  ([m6-level2-narrow-verify2.md](../benchmarks/m6-level2-narrow-verify2.md)),
  and round 3 after the budget-efficiency fixes converted **3/6**
  (deterministic 3/5)
  ([m6-level2-narrow-verify3.md](../benchmarks/m6-level2-narrow-verify3.md)).
  An earlier narrow round had converted 4/6 on the rounds it captured, but its
  run stopped at 53 of 54 traces (410,256 tokens), so it is not a verdict and
  is not counted as one
  ([m6-level2-narrow-verify-incomplete.md](../benchmarks/m6-level2-narrow-verify-incomplete.md)).
  So per the acceptance plan's **option 3, status disclosure**
  investment stopped for good and the milestone stays open
  on the strength of that record. The service scope promised for M6 is a
  **bounded, evidence-checkable agent walkthrough** over the frozen set — not
  a claim that the agent meets the ≥90% acceptance bar — and the agent's
  answers remain **leads**, never verified findings.
- **M7 — client-ready deliverables.** Offline single-file HTML reports
  (`analyze --html`), minimal evidence packages (`dexatlas export`), and three
  rewritten case studies. The per-case deliverables are committed under
  [case-studies/attachments/](../case-studies/attachments/) — nine files:
  report Markdown/JSON/HTML plus a minimal evidence package for the demo/API
  case (`apk_80a8fe0e81204c9f`) and the obfuscated case
  (`apk_2f8d476fb9e71ac4`), each generated by the commands printed in its
  study and checked with `verify_package`.
  [case-studies/README.md](../case-studies/README.md)
- **M8 — installs, contracts, failure recovery.** `--workspace`/`-w` on every
  read/write command; the public contract table frozen with **49** live checks
  (28 REST + 6 MCP + 15 CLI) and the contract snapshot tests
  ([public-contracts.md](../architecture/public-contracts.md)); 49 is the number of
  checks in the table, and no single run executes all of them — the all-backends run
  executes 48 and passes all 48 with exit 0, because the two CLI assertions
  branch on the backends that took part in the analysis, not on the machine;
  clean-install/Docker/failure-recovery rehearsal
  ([m8-install-rehearsal.md](../reports/m8-install-rehearsal.md)); and the
  contract change that closes the silent-partial-run gap: a finished analysis
  whose every code backend failed now answers **exit code 6
  (`EXIT_NO_INDEX`)** instead of 0.
- **M9 — showcase.** Bilingual README refresh (English and 简体中文), a
  documentation map, third-party attribution and the roadmap table; the
  Upwork materials remain unpublished drafts.
- **Documentation corrections.** The install guide no longer claims that no
  APK is committed: five first-party sample APKs live under `examples/` with
  their sources, and the third-party fixtures still come from
  `scripts/fetch-fixtures.sh`.

## Verification

Every figure below is measured, not written: the report they come from is
written by the measuring script from a complete run, so these numbers are
copied out of a measurement rather than typed in by hand.

- **Test suite — 1612 tests** (1465 fast + 147 integration). The full
  environment run reports **1612 passed + 0 xfailed + 0 skipped**; a skip is
  not a pass, so the zero is part of the claim.
  ([phase1-execution-report.md](../reports/phase1-execution-report.md))
- **First-party coverage — 93.3%** (7117 / 7631 lines). The report prints the
  modules below 90% rather than hiding them, and states plainly that a plain
  `pytest --cov` cannot see `tools/androguard/worker.py`, because that module
  runs in another process — the measurement is subprocess-aware, so that
  process is counted too.

## What this release does NOT include

- No claim that the agent meets the service acceptance bar: the first
  three-round batch measured 40.0% against the ≥90% bar, and the post-fix
  full three-round retest scored 49/60 = 81.7% (15/16/18 per round) — the
  three-round bar is still unmet
  ([m6-level2-retest4.md](../benchmarks/m6-level2-retest4.md)). Agent answers
  remain **leads**, never verified findings.
- No native/dynamic analysis — `DEXATLAS_GHIDRA_PATH`/`DEXATLAS_RIZIN_PATH`
  are reserved and unread.
- No plugin ecosystem beyond the tool registry.
- No published Upwork service page; no macOS verification (Windows/Linux
  tested).
- Not a security audit, penetration test, malware verdict, or
  packer/obfuscation bypass.
- No completed independent acceptance: the M10 acceptance package is drafted
  and self-checked, but no independent reviewer has run it. Nothing in these
  release notes is a completed acceptance.

## Known limitations

- A run in which every code backend fails can still record `completed` with a
  readable manifest — Apktool may write the manifest before it is stopped.
  The run now answers exit code 6 (`EXIT_NO_INDEX`) instead of 0, and the
  same fact is carried by `errors[]`, `summary.index_complete == false` and
  `run.completeness = "partial"` (contract table §8.1, and
  [the proposal that introduced it](../proposals/exit-code-partial-read.md)).
- Level-2 boundary: one model, temperature 0, first-party small APKs, a
  closed 20-question set; A/B and DexAtlas ran under different budgets, so
  configuration differences are not model-quality claims. The post-fix
  three-round retest scored 49/60 = 81.7% (15/16/18) — the per-round line
  (≥16/20) was met in r2 and r3, not in r1, and the three-round ≥90% bar
  remains unmet ([m6-level2-retest4.md](../benchmarks/m6-level2-retest4.md)).
- The samples under `examples/` include a hand-written obfuscated app; it
  covers short class/method names, not control-flow obfuscation or commercial
  packers.

## Upgrading from v0.2.0

- **New exit code 6 (`EXIT_NO_INDEX`).** `analyze` returns 6 when the run
  finished but no symbol index could be built (every code backend failed; the
  manifest may still be readable). The meanings of 0–5 are unchanged from
  v0.2.0 — exit 5 (`EXIT_TRUNCATED`) already shipped there — but 0's
  extension narrows: callers that treated 0 as "fully successful" should
  distinguish the two with `exit_code in (0, 6)` or
  `summary.index_complete`. The report, manifest and `schema_version` are
  unchanged.
- **`--workspace`/`-w` on every read/write command** (in v0.2.0 only
  `analyze` accepted it). A query command pointed at a missing directory
  exits 2 rather than creating an empty workspace.
- **MCP tools: 10 → 11.** `find_resource_declarations` resolves a resource
  name or value to its declaring files; the ten previous tools are unchanged.
- **Agent default budget raised** to 120,000 tokens / 16 iterations / 120 s,
  plan cap 40 steps (was 20,000 / 8 / 120 s / 12). The four
  `DEXATLAS_AGENT_*` environment overrides are unchanged. The agent JSON
  report adds a `convergence` object and the Markdown report a "How the task
  converged" section — both additive.
- **New: `--html`** (offline single-file HTML report) **and `export`**
  (minimal evidence package). Report `schema_version=3` and evidence-package
  `schema_version=1` are unchanged.
- **Fixed:** the API-served report no longer drops the APK archive facts
  (hash and size), repeated analyses no longer drift the CLI report's
  `created_at` from the stored row, and `androguard:AndroidManifest.xml`
  provenance resolves again.
- **Install:** `uv sync --extra dev --extra analysis --extra mcp --extra demo`
  from the lockfile (v0.2.0 documented `uv pip install -e ".[analysis]"`).

## What was reviewed before the tag

The v1.0.0 release text and the material behind it went through several rounds
of independent review before the tag was cut. Each round read the release text
against the source it claims to come from, and against the other outward-facing
texts, and each round left a written record. What the rounds found was mostly
not new facts but stale ones — a count that had been regenerated somewhere
else, two sentences in one place that said opposite things, an output quoted
from another document and read as a current claim, a premise about one machine
mistaken for a promise about the product.

**Three-way source reconciliation.** The CHANGELOG's `[1.0.0]` section, these
release notes and the GitHub Release body draft were read against each other.
Twelve items still needed reconciling when this ran, and the report separated
the real conflicts from the differences of detail that were deliberate
([changelog-vs-release-notes.md](../reports/changelog-vs-release-notes.md)).

**Reader-perspective walkthrough.** The M10 acceptance material was re-read as
an outside reviewer who had never seen the project, looking for the places
where a reader would stall or misjudge rather than for the numbers again. The
first round found 29 issues; a second round judged those 29 against the
corrected tree and found 23 closed, 5 still open, 1 the first round had judged
wrongly, and 8 new ones
([m10-reader-walkthrough.md](../reports/m10-reader-walkthrough.md),
[m10-reader-walkthrough-2nd.md](../reports/m10-reader-walkthrough-2nd.md)).

**Whole-tree stale-number sweep.** Every number under `docs/` and in the README
was reconciled against the document it comes from; 52 places still carried a
superseded value ([stale-number-scan.md](../reports/stale-number-scan.md)).

**Fields and contracts.** The Upwork-facing material was measured against the
platform's field limits and its character tables re-computed
([outreach-final-review.md](../reports/outreach-final-review.md),
[outreach-recheck.md](../reports/outreach-recheck.md)). The public contract
table's checks were run live rather than counted: the table lists 49 checks
(28 REST + 6 MCP + 15 CLI), that is a static count no single run executes in
full, and the current script's two live runs ended 48/48 with all three
backends present and 47/47 with only androguard
([public-contracts.md](../architecture/public-contracts.md) §7).

**The measurement itself.** A read-only audit found that `.coverage` was one
file per checkout, which the measurement script deleted, appended to and re-read
whole, with no mutual exclusion between those steps: two concurrent runs could
overwrite each other's data, and a partial file could reach the report as a
complete measurement ([coverage-guard-audit.md](../reports/coverage-guard-audit.md)).
The measurement now writes to a private data file and takes a per-checkout
lock.

**English-reader final pass.** The five outward-facing English texts were read
once more for how a reader without background would take them; 16 of the
report's 49 findings were marked as the ones that would make a reader misjudge
the project ([english-reader-review.md](../reports/english-reader-review.md)).

### What the rounds caught

The recurring types, each one a place where a reader following the text would
have been misled:

- Two statements in the same CHANGELOG section contradicted each other: the
  MCP tool count went from ten to eleven in one line and was still ten in
  another, and exit code 6 was described as implemented in one place and as a
  proposal only in another.
- The same count carried two values across documents: the contract checks were
  written as 46 (26 REST + 6 MCP + 14 CLI) while the script behind them had
  already grown to 49 (28 REST + 6 MCP + 15 CLI), and the outreach material
  still carried the previous test count and the previous percentage where the
  release measurement says 1612 tests at 93.3%
  ([phase1-execution-report.md](../reports/phase1-execution-report.md)).
- An output quoted from another document read as a current claim: the CHANGELOG
  cited a benchmark run that happens to score the same as the run that
  superseded it — 49/60, but with a different per-round composition and more
  than 300 lines apart — so a reader could take the earlier run's numbers as
  the current ones.
- A number that held only inside the tool that produced it was written as a
  general result: one benchmark report's "three-round first-test total"
  column was filled from the first round alone while the denominator said 60.
  The correction went into the generating script, not into the Markdown.
- A premise about the environment was hard-wired into an assertion: two CLI
  checks in `scripts/verify-public-contracts.py` asserted what a machine
  without a source or resource backend does, so a correct tree with all three
  backends installed was judged failing. The assertions now branch on the
  backends that actually took part in that run.

The record lives under `docs/reports/`. The index at
[docs/reports/README.md](../reports/README.md) says what each report answers,
when it is worth reading, and which of them are history rather than current
state; the reader-facing path for re-deriving the numbers themselves is
[how-to-verify.md](../how-to-verify.md) (in Chinese).

### What this is not

These rounds were the authors' own independent reviews and self-checks, run
against the release text before the tag. They are not an external independent
acceptance. M10's independent acceptance has not started: the acceptance
package is drafted and self-checked, but no independent reviewer has run it.
Nothing in this section is an acceptance result.
