# DexAtlas v1.0.0 — The Evidence-First Portfolio Milestone

DexAtlas v1.0.0 is Phase 3's portfolio-and-delivery milestone: the claims
baseline re-verified against the code (M5), a frozen 20-question service
regression set for the agent with honest level-2 results (M6), client-ready
deliverables — offline HTML reports, minimal evidence packages and rewritten
case studies with their attachments on disk (M7), the public contract table,
workspace-wide `--workspace` and a new exit code for runs that indexed nothing
(M8), and a bilingual README showcase (M9). It is for a reviewer, a client or
an agent that needs Android static analysis whose every number traces back to
the bytes it came from. The boundary is one sentence: this is static,
evidence-first analysis, and the agent inside it is bounded — its answers are
leads to verify, never verified findings.

## What's in this release

- **M5 — claims baseline.** Every outward claim re-checked against the code
  and committed traces; the three benchmarks regenerate byte-for-byte from
  their traces. [phase3-baseline.md](../reports/phase3-baseline.md)
- **M6 — frozen service regression set (20 questions).** Level-0
  deterministic scoring is 20/20 with no model in the loop; the level-1
  scripted drill proves the pipeline end to end. The level-2 real-model batch
  (MiniMax-M3.1-Flash, three independent rounds) scored **24/60 = 40.0%
  (45%/40%/35% per round) against the ≥90% acceptance bar — not passed**
  ([m6-level2-real.md](../benchmarks/m6-level2-real.md)). After the
  execution-layer fixes (four) and the C2 single-word fallback, the full
  three-round retest on the complete 20-question denominator scored
  **49/60 = 81.7%
  (15/16/18 per round; r2 and r3 met the per-round ≥16/20 line, r1 did
  not)** — still below the three-round ≥90% bar (A 21/60, B 21/60; traces
  1,182,356 tokens)
  ([m6-level2-retest4.md](../benchmarks/m6-level2-retest4.md); the
  single-round retest that first met the per-round line is recorded in
  [m6-level2-retest2.md](../benchmarks/m6-level2-retest2.md)). Two further
  narrow verification rounds over the six known failure surfaces (6 questions
  × 3 rounds × 3 configurations each) also stayed below the narrow gate:
  round 2 converted **2/6** (deterministic 2/5)
  ([m6-level2-narrow-verify2.md](../benchmarks/m6-level2-narrow-verify2.md)),
  and round 3 after the budget-efficiency fixes converted **3/6**
  (deterministic 3/5)
  ([m6-level2-narrow-verify3.md](../benchmarks/m6-level2-narrow-verify3.md)).
  An earlier narrow round had converted 4/6 on the rounds it captured, but its
  run stopped at 53 of 54 traces (410,256 tokens), so it is not a verdict and
  is not counted as one
  ([m6-level2-narrow-verify-incomplete.md](../benchmarks/m6-level2-narrow-verify-incomplete.md)).
  So per the verification plan investment stopped for good and the milestone
  stays open on the strength of that record. The service scope promised for
  M6 is a **bounded, evidence-checkable agent walkthrough** over the frozen
  set — not a claim that the agent meets the ≥90% acceptance bar — and the
  agent's answers remain **leads**, never verified findings.
- **M7 — client-ready deliverables.** Offline single-file HTML reports
  (`analyze --html`), minimal evidence packages (`dexatlas export`), and three
  rewritten case studies. The per-case deliverables are committed under
  [case-studies/attachments/](../case-studies/attachments/) — nine files:
  report Markdown/JSON/HTML plus a minimal evidence package for the demo/API
  case (`apk_80a8fe0e81204c9f`) and the obfuscated case
  (`apk_2f8d476fb9e71ac4`), each generated by the commands printed in its
  study and checked with `verify_package`.
  [case-studies/README.md](../case-studies/README.md)
- **M8 — installs, contracts, failure recovery.** `--workspace`/`-w` on every
  read/write command; the public contract table frozen with **46/46** live
  checks (26 REST + 6 MCP + 14 CLI) and the contract snapshot tests
  ([public-contracts.md](../architecture/public-contracts.md));
  clean-install/Docker/failure-recovery rehearsal
  ([m8-install-rehearsal.md](../reports/m8-install-rehearsal.md)); and the
  contract change that closes the silent-partial-run gap: a finished analysis
  whose every code backend failed now answers **exit code 6
  (`EXIT_NO_INDEX`)** instead of 0.
- **M9 — showcase.** Bilingual README refresh (English and 简体中文), a
  documentation map, third-party attribution and the roadmap table; the
  Upwork materials remain unpublished drafts.
- **Documentation corrections.** The install guide no longer claims that no
  APK is committed: five first-party sample APKs live under `examples/` with
  their sources, and the third-party fixtures still come from
  `scripts/fetch-fixtures.sh`.

## What this release does NOT include

- No claim that the agent meets the service acceptance bar: the first
  three-round batch measured 40.0% against the ≥90% bar, and the post-fix
  full three-round retest scored 49/60 = 81.7% (15/16/18 per round) — the
  three-round bar is still unmet
  ([m6-level2-retest4.md](../benchmarks/m6-level2-retest4.md)). Agent answers
  remain **leads**, never verified findings.
- No native/dynamic analysis — `DEXATLAS_GHIDRA_PATH`/`DEXATLAS_RIZIN_PATH`
  are reserved and unread.
- No plugin ecosystem beyond the tool registry.
- No published Upwork service page; no macOS verification (Windows/Linux
  tested).
- Not a security audit, penetration test, malware verdict, or
  packer/obfuscation bypass.
- No completed independent acceptance: the M10 acceptance package is drafted
  and self-checked, but no independent reviewer has run it. Nothing in these
  release notes is a completed acceptance.

## Known limitations

- A run in which every code backend fails can still record `completed` with a
  readable manifest — Apktool may write the manifest before it is stopped.
  The run now answers exit code 6 (`EXIT_NO_INDEX`) instead of 0, and the
  same fact is carried by `errors[]`, `summary.index_complete == false` and
  `run.completeness = "partial"` (contract table §8.1, and
  [the proposal that introduced it](../proposals/exit-code-partial-read.md)).
- Level-2 boundary: one model, temperature 0, first-party small APKs, a
  closed 20-question set; A/B and DexAtlas ran under different budgets, so
  configuration differences are not model-quality claims. The post-fix
  three-round retest scored 49/60 = 81.7% (15/16/18) — the per-round line
  (≥16/20) was met in r2 and r3, not in r1, and the three-round ≥90% bar
  remains unmet ([m6-level2-retest4.md](../benchmarks/m6-level2-retest4.md)).
- The samples under `examples/` include a hand-written obfuscated app; it
  covers short class/method names, not control-flow obfuscation or commercial
  packers.

## Upgrading from v0.2.0

- **New exit code 6 (`EXIT_NO_INDEX`).** `analyze` returns 6 when the run
  finished but no symbol index could be built (every code backend failed; the
  manifest may still be readable). The meanings of 0–5 are unchanged from
  v0.2.0 — exit 5 (`EXIT_TRUNCATED`) already shipped there — but 0's
  extension narrows: callers that treated 0 as "fully successful" should
  distinguish the two with `exit_code in (0, 6)` or
  `summary.index_complete`. The report, manifest and `schema_version` are
  unchanged.
- **`--workspace`/`-w` on every read/write command** (in v0.2.0 only
  `analyze` accepted it). A query command pointed at a missing directory
  exits 2 rather than creating an empty workspace.
- **MCP tools: 10 → 11.** `find_resource_declarations` resolves a resource
  name or value to its declaring files; the ten previous tools are unchanged.
- **Agent default budget raised** to 120,000 tokens / 16 iterations / 120 s,
  plan cap 40 steps (was 20,000 / 8 / 120 s / 12). The four
  `DEXATLAS_AGENT_*` environment overrides are unchanged. The agent JSON
  report adds a `convergence` object and the Markdown report a "How the task
  converged" section — both additive.
- **New: `--html`** (offline single-file HTML report) **and `export`**
  (minimal evidence package). Report `schema_version=3` and evidence-package
  `schema_version=1` are unchanged.
- **Fixed:** the API-served report no longer drops the APK archive facts
  (hash and size), repeated analyses no longer drift the CLI report's
  `created_at` from the stored row, and `androguard:AndroidManifest.xml`
  provenance resolves again.
- **Install:** `uv sync --extra dev --extra analysis --extra mcp --extra demo`
  from the lockfile (v0.2.0 documented `uv pip install -e ".[analysis]"`).
