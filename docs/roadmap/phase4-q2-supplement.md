# Phase 4 Q2 补充单 — 原创桌面应用（Tauri + React）

**日期：** 2026-11-24 · **性质：** 追加范围执行单（Q2）· **状态：** 已批准，待实施
**来源：** 用户在 Phase 4 M15 收口后的新授权。本单**解除 Portfolio Freeze 中关于"新页面、新平台"的限制**，批准在**同一仓库**内立项并开发一个原创桌面应用。

## 1. 为什么要追加

v1.0.2 发布后，项目对外形态只有两个：CLI/API/MCP 和浏览器 Workbench。用户明确要求做**原创桌面应用**，并要求按"定义产品方向 → 搭建信息结构 → 控制视觉语言 → 按标准迭代"四步法设计和完善 UI。本单把该要求落成可执行、可验收的阶段目标。

本单**不替代**已完成的 Phase 4 M11–M15；它是 Phase 4 之后的 Q2 补充阶段。主仓库保留现有 CLI/REST/MCP/Workbench 的公共契约，桌面应用作为新前端形态叠加在同一分析核心上。

## 3. UI 资产复用策略

E 盘已有 UI 参考集 `E:\ui-libraries`（17 个仓库）与技能集 `E:\ui-skills`。本单采用"**看规范、抄结构、不整库依赖**"的策略：

- **设计 token 参考**：`design-systems/primer-primitives` 的 type scale、color token、spacing token，用来约束桌面应用的字号层级、间距节奏和强调色规则；最终 token 以本单 §2.3 的视觉决策为准。
- **信息密度参考**：`design-systems/carbon` 的 compact/condensed 分级，用于分析页、日志区和表格的高密度场景。
- **组件结构参考**：`web/shadcn-ui` 的组件源码组织方式（复制进项目、按需改造），不把 shadcn 作为运行时依赖整体引入。
- **行为与可访问性参考**：`web/radix-primitives` 的交互行为（对话框、抽屉、下拉、焦点管理），按需引入单个 primitive。
- **图标**：`foundations/lucide` 的线性图标风格，与 §2.3 的"线性图标为主"一致。
- **参考图气质**：用户提供的四张"定义产品方向 / 搭建信息结构 / 控制视觉语言 / 按标准迭代"幻灯片，作为首屏与卡片语言的视觉方向，不直接复制其插画资产。

## 4. 范围

### 4.1 必须完成

- 在同一仓库内新增桌面应用目录（Tauri + React + TypeScript），不破坏现有 Python 包、CLI、REST、MCP、报告 schema、证据 locator、状态码与退出码。
- 建立桌面 UI 设计规范文档：信息架构、页面清单、组件清单、视觉 token、状态矩阵、键盘行为。
- 建立桌面组件库：至少覆盖 Button、Card、Panel、Table、StatusBadge、Sidebar、Breadcrumbs、Dialog/Drawer、Tabs、Input、EmptyState、ErrorState、LoadingState、PartialBanner、Timeline、SourcePreview、DragDropUploader。
- 实现核心页面：
  1. 首页（拖拽上传 + 最近项目）；
  2. 分析进行中页（阶段进度 + 实时日志 + 后端状态）；
  3. 项目详情页（三栏：列表 / 主体 / 证据抽屉）；
  4. 证据页与 locator 解析视图；
  5. 报告页（Markdown/JSON 导出入口）；
  6. 设置页（后端路径、模型配置、版本信息收口处）。
- 与现有分析核心打通：桌面应用通过本地进程/HTTP 调用 DexAtlas 现有能力，不复制分析逻辑。
- 交付可运行 Tauri 原型，并在 Windows 上启动截图。

### 4.2 明确不纳入

- 不新增 Ghidra、Frida、JNI 深度分析、新漏洞规则、认证、多租户、云端 APK 上传、分布式队列或新的数据库层。
- 不改变 REST、MCP、CLI、报告 schema、证据 locator、公共状态码和退出码。
- 不做应用商店分发、自动更新服务、签名证书采购或跨平台发布矩阵；第一验收平台是 Windows。
- 不把浏览器 Workbench 删除；两者在过渡期并存。

## 5. 里程碑

### Q2-M1 — 设计规范与组件库

1. 输出 `docs/roadmap/phase4-q2-design.md`：信息架构、页面清单、组件清单、视觉 token、状态矩阵。
2. 建立桌面前端工程与基础 token。
3. 完成核心组件库与 Storybook 式展示页（或等价的组件画廊页面）。

**退出条件：** 所有基础组件在同一处定义并可预览；视觉 token 覆盖颜色、字体、间距、圆角、阴影、渐变、焦点环。

### Q2-M2 — 核心工作流

1. 首页拖拽上传与文件校验。
2. 分析进行中页：阶段进度、实时日志、后端状态。
3. 项目详情三栏布局与证据抽屉。
4. 报告导出入口。

**退出条件：** 用真实 `examples/demo-app/demo.apk` 走通"拖入 APK → 查看证据 → 导出报告"三步，全程键盘可达。

### Q2-M3 — 打磨与验收

1. 空态、加载态、错误态、部分态全覆盖。
2. 动画与微交互：过渡、hover、焦点、展开收起。
3. Windows 下 Tauri 构建与启动。
4. 截图对照四步标准，形成验收记录。

**退出条件：** 可运行原型在 Windows 启动；核心页面截图齐全；四步标准逐项通过；不引入主仓库公共契约破坏。

## 7. 冻结状态变更

本单批准后，Portfolio Freeze 的范围调整为：

- **解冻：** 桌面应用（Tauri + React）相关的新增代码、页面、组件、文档与必要接线。
- **继续冻结：** 新分析后端、新漏洞规则、REST/MCP/CLI 契约变更、报告 schema 变更、新外部平台发布动作。
- **收尾义务：** Q2 桌面应用阶段结束时，需再次明确下一阶段的冻结或解冻范围，不能默认延续本单的解冻状态。

## 8. 最终决策记录

- 形态：**原创桌面应用**，不是 Electron，也不是纯网页壳。
- 技术栈：**Tauri + React + TypeScript**。
- 视觉：**高端浅色工作室**，深海军蓝 + 淡紫橙渐变，大圆角 + 轻阴影 + 半透明渐变，线性图标为主。
- 信息架构：左侧栏导航；分析页三区；详情页三栏；首屏突出拖拽上传与最近项目。
- 质量标准：三步主链路、组件库化、状态诚实、键盘可达、可运行原型 + 截图验收。
- 仓库策略：**同一仓库**开发，Portfolio Freeze 针对性解除。
