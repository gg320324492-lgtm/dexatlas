# v1.0.0 发版 commit 草案（不执行发版）

**性质：** 本文件是 v1.0.0 发版 commit 的完整变更清单与 commit message 草案，
供作者在发版当日执行。**本草案不执行发版**：不改 `src/dexatlas/__init__.py`
的版本号、不打 tag、不 push tag、不创建 GitHub Release。执行顺序、门禁与
前提见 [v1.0.0-release-runbook.md](v1.0.0-release-runbook.md)；「发什么、
凭什么」见 [v1.0.0-release-checklist.md](v1.0.0-release-checklist.md)。

**基线：** `claude/m6-level2-verify` 合并成果 `e4f3011`（本草案分支
`claude/release-draft` 即基于该 commit）。

**红线（沿用项目规则）：** 报告生成数字绝不手改；发版 commit 一旦完成完整
重测，不得再改 `src/`、`tests/`、`benchmarks/`；所有对外数字与下文草案
必须能在已落盘报告中找到出处。

### 1.3 docs/HANDOVER.md

发版时把 HANDOVER.md 的三处「planned / target v1.0.0」改为完成时，并把
latest release 从 v0.2.0 改指 v1.0.0。逐处如下（行号为 `e4f3011` 基准）：

- **第 11–12 行**：`The state itself is the tag **v0.2.0** (2026-11-14),
  which is the latest release; main may be ahead of it.` →
  `The state itself is the tag **v1.0.0** (<发版日期，YYYY-MM-DD>, filled at
  release time), which is the latest release; main may be ahead of it.`
- **第 34 行**：`The next planned work is Phase 3 (target v1.0.0):` →
  `Phase 3 was delivered in this release. The next planned work:`
- **第 100–101 行**：`…and v0.2.0 shipped the lot. The next planned work is
  **Phase 3 (target v1.0.0)**; follow the revised` → `…and v0.2.0 shipped the
  lot. Phase 3 was delivered in this release (tagged <发版日期>); the
  remaining follow-ups (independent acceptance, readiness re-scoring) are
  tracked in docs/status.md; follow the revised`
- **第 22、23–24 行**：「v0.2.0 shipped M0–M3 plus the workbench」等——
  **不改**（历史事实）。

措辞刻意写 “in this release” 而不是 “in v1.0.0”：tag 打上之前 v1.0.0 不是
已发布版本，`check-version-claims` 会把草案文件里的 “delivered in v1.0.0”
按「宣称已发布」计 finding；执行发版时按上表替换后，finding 即消失。

```bash
# ⑤ git add -A && git commit（用上文 §2 message）
# ⑥ git tag -a v1.0.0（annotated，指向 ⑤ 的最终 commit）
# ⑦ HTTPS_PROXY=http://127.0.0.1:7897 git push origin <分支> && … push origin v1.0.0
# ⑧ 等 CI 全绿 → gh release create（须作者执行或明确授权）
```

## 4. 本草案分支与发版 commit 的关系

本分支 `claude/release-draft`（基线 `e4f3011`）只提交「草案期可定稿」的内容：
CHANGELOG `[Unreleased]` 的 1.0.0 定稿文字（标题仍为 Unreleased、附发版时
应用说明）、`docs/releases/v1.0.0.md` 校对、runbook 的 HANDOVER 补丁说明
（§6.1/§6.2）、以及窄验证二轮 2/5 转抄错误的修正。**发版 commit = 本分支
改动 + §1.1–1.5 的机械步骤**，在发版当日于当时的主线树上执行并重测。
