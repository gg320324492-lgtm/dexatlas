## 2. 排序与理由

排序口径只有一条：**对「能不能接活、能不能被信任」的影响**。
拆成两个可判定的问句：

- **能不能接活**——这份材料让一个真实客户愿意把活派给我吗？
- **能不能被信任**——对方核到出处时，会不会发现对不上？

| 档 | 候选 | 为什么在这一档 |
|---|---|---|
| **P0** | C1 材料一致性收口 | 它是 M10 的**前置**：读者手里的材料自己先得立得住。第三轮走查的判语是「读者会做出一份针对另一棵树的验收结论」（[m10-reader-walkthrough-3rd.md:489](m10-reader-walkthrough-3rd.md#L489)）——材料矛盾不是小瑕疵，它会让唯一的独立验收作废。纯仓库内可做，不消耗任何外部资源，先做。 |
| **P0** | C2 M10 独立验收 | 它是「对外说已完成验收」的**唯一门槛**：准备度单项增量最大（GitHub +10.0、Upwork +8.75，[portfolio-readiness-2026-11-15-recheck.md:127](portfolio-readiness-2026-11-15-recheck.md#L127)），且 Phase 3 退出标准把它列为必答项（[phase3-plan.md:219](../roadmap/phase3-plan.md#L219)）。**不能被仓库内任何工作替代**（[portfolio-readiness-2026-11-15-recheck.md:236](portfolio-readiness-2026-11-15-recheck.md#L236)）。 |
| **P0** | C3 方向 B 承诺宽度定案 | 它决定「接活时能承诺到多宽」。49/60 = 81.7% 未达自定的 90% 线（[status.md:134](../status.md#L134)），诚实答案只能是收窄承诺或明说未达线。**这一项便宜（改文案）、无外部依赖、且越晚做越贵**——它卡着方向 B 的所有对外表述。 |
| **P1** | C4、C5、C6 | 影响**交付可信度**：证据包与样本的对应关系（三个包实际只覆盖两次分析，sha256 实测见 C4）、第三个样本有没有证据包、镜像里能不能跑案例。这些是「客户拿到的东西对不对得上」。 |
| **P1** | C7 对外数字核对 | 对外数字每发一次就会过期（[next-engagements.md:313](next-engagements.md#L313)），过期一次就是一次「文档没跟上」的破绽。 |
| **P1** | C8 「渲染某一次运行」 | 真实需求（客户要留档某一次运行的证据），但它**动公共契约**，且 Phase 3 明写「不继续扩功能来回避对外验证」（[phase3-plan.md:49](../roadmap/phase3-plan.md#L49)）→ 排在 M10 之后。 |
| **P2** | C9、C10 | 发布的必要条件，但**需要作者的真值**（联系方式、时区）与他对「哪些文件能外发」的判断；仓库替代不了人。 |
| **P2** | C13 | 引用检查器覆盖不到报告层：没进 `DOCS` 名单的文档，坏引用在 CI 里全是绿的（这一轮实测三类：指向空行、越过文件末尾、裸引用无解）。纯仓库内可做，但它改 `tests/` → 改源指纹 → 要等 v1.0.0 发完再动。 |
| **P2** | C11 | 需要外部读者，可与 C2 同一次邀请（[phase3-plan.md:214](../roadmap/phase3-plan.md#L214)）。 |
| **P2** | C12 | 需要联网与平台账号，且**在真实表单上**才有意义（[publish-review.md:326](../outreach/publish-review.md#L326)）。 |

> **一句话**：C1 是让 C2 有意义的前提，C2 是「被信任」的门槛，
> C3 是「能接活」的边界；P1 决定交付件对不对得上，P2 是发布的行政条件。

**怎么算做完（判据）**

**依赖**：全在仓库内，无外部依赖；但**要等 v1.0.0 发布完成**——它改 `tests/`，
会改源指纹，源指纹一变，报告数字就得重新测量、tag 还得重打。

**估时与依据**：约 **1 工程日**（改检查器 + 三条规则 + 回归测试 + 修五份文档里的坏引用 +
一次重测量与数字同步）。
