# DexAtlas v1.1.0 — Q2 desktop application and stability batch

v1.1.0 ships the **Q2 desktop application** (Tauri 2 + React 19 + TypeScript,
alongside the existing CLI/REST/MCP/Workbench) and the post-Q2 stability batch.
Since v1.0.2, main has gained 41 commits merged through nine reviewed pull
requests.

## What's new

### Desktop application — DexAtlas Studio

- **Design specification first** ([desktop-app.md](../architecture/desktop-app.md)):
  information architecture, visual tokens (deep navy + lavender/apricot
  gradients, 16px radius, two shadow levels, gradients on the home screen only),
  a 19-component inventory, a state matrix and keyboard behaviour.
- **Component library and gallery**: 21 base components plus a gallery page;
  every page is built from the library.
- **Core workflow on real data**: home drag-and-drop upload (`POST /api/analyze`
  with `.apk` validation, oversize and same-hash hints) → analysis-in-progress
  page (stage progress driven by run state, status timeline, backend health) →
  project detail in three columns with an evidence drawer (real locators,
  resolve actions) → report export (Markdown/JSON download) → evidence search →
  settings.
- **Distributable artifacts**: `npx tauri build` produces a self-contained
  release exe and MSI/NSIS installers; the release form was verified on real
  hardware (native fetch blocked by CORS, plugin-http channel 200; home,
  detail and export all usable).
- **Performance baseline**: nine on-device measurements all within bounds
  (cold start 892 ms, slowest route 82 ms, evidence render 64 ms, export
  56–78 ms, polling CPU 0.06 %, stable memory, no layout breakage when
  resizing), recorded in
  [phase4-q2-perf-walkthrough.md](phase4-q2-perf-walkthrough.md).
- **Acceptance**: all eight dimensions of the Q2 supplement's §6 matrix pass;
  screenshots and evidence are in
  [phase4-q2-acceptance.md](phase4-q2-acceptance.md).

### Workbench endpoints the desktop depends on

- `GET /api/backends`, `GET /api/projects/{id}/runs`,
  `GET /api/projects/{id}/runs/{run_id}`, `POST /api/projects/{id}/cancel`
  (202/409), reusing the MCP contract shapes; their regression tests were
  written red first.
- **Orphaned-run reconciliation**: at start-up a workbench rewrites the runs a
  dead process left saying "running" as `failed`, with the reason recorded
  (the root cause of a `strings.apk` that had read as in progress since
  23 Nov); analyses this process is running are left alone, and the sweep is
  idempotent. Two new regression tests cover both paths.

### Desktop stability and accessibility

- Exponential backoff with a manual refresh for the analysis page's polling; a
  skeleton list for the home page; upload edge-case hints; unified error
  wording (`describeError`, no more `undefined:` prefixes).
- A skip-link on the core path (acceptance item A-7); a long-token line-break
  fix in the log panel; content centered with a max width at 1920 px; export
  button wording unified.

## Verification

The suite is **1819** tests (1670 fast + 149 integration), **1818 passed,
1 skipped, 0 xfailed**, with **93.3 %** first-party coverage (7375/7904 lines),
measured by `scripts/refresh-report-figures.py` against the released tree in a
complete environment (backend paths, fixtures, Pillow, ffmpeg; nothing hidden
behind skips). ruff lint + format, `mypy` strict, `vulture`, the citation
checker, the version-claim checker, the release-number checker and the
social-preview check all pass. `npm run build` is clean and the Tauri release
form was exercised end to end on real hardware (upload → evidence → export).

## What this release does not claim

- The desktop application's first acceptance platform is Windows; macOS and
  Linux are unverified.
- The stage-level progress in the analysis page is driven by run state; the
  granularity the backend does not expose is simulated in the front end and
  labelled as such. The backend offers no live log stream — the log panel
  shows the polling record, and says so.
- No app-store distribution, update service or signing certificate is part of
  this release; the installers are local build artifacts.
- The desktop application calls the existing analysis core over local HTTP; it
  adds no new analysis capability.
