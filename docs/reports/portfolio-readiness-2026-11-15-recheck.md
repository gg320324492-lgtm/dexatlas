## 2. 加权计算与基线对照

计算方式与基线相同：每项贡献＝分值 ÷ 4 × 该平台权重，两平台分别求和。

| 平台 | 基线（2026-11-15） | 本次自评 | 距 90% 目标 |
|---|---:|---:|---:|
| GitHub | 约 75% | **77.5%** | 差 **12.5 个百分点** |
| Upwork | 约 65% | **68.75%** | 差 **21.25 个百分点** |

- GitHub：4×30 + 3×20 + 3×10 + 2×10 + 3×25 + 1×5 = 310 → **77.5%**。
- Upwork：4×20 + 3×15 + 3×15 + 2×25 + 3×15 + 1×10 = 275 → **68.75%**。

提升来自 Agent 维度（2→3）与首次试用维度的证据增厚；Upwork 权重最高的
「客户交付件与服务边界」（25%）停留在 2 分，是两平台差距拉大的主因。
与基线一致，建议把结论理解为区间而非精确值：GitHub 约 75–80%、Upwork 约 65–72%。

## 3. 逐维度证据与扣分原因

### 3.1 核心工程与证据链 — 4 / 4（维持）

证据链模型（结论分级、provenance、后端失败为值）经 M4 源码评审验收，本轮未回退。
[公共契约表](../architecture/public-contracts.md)已成文并固化为测试，M8-1 修复
（证据包裸树 locator 误判）带红→绿回归测试。扣分（为何不是满分之外更高）：该维度
已到等级定义上限；范围仍限于已验收能力，插件化调度等扩展不在声明范围内。

### 3.2 首次试用与复现 — 3 / 3（维持，证据增厚）

新增证据：[M8 演练](m8-install-rehearsal.md)在干净 worktree 实测 Windows 全链
（uv sync → 后端 → fixtures → 首次分析 → 报告 → export → verify）、Docker 构建与
容器内运行、六项故障恢复；Linux 由 CI 七 job 覆盖；[install.md](../install.md) 的
extras 组合已修正；查询命令统一 `--workspace`。扣分：演练由作者执行，macOS 未验证，
仍无独立首次用户从零安装的验收记录（该项属 M10）。

### 3.3 Agent 可用性与评测可信度 — 2 → 3

升级理由：基线时的「默认预算与开放问题缺口」已有有依据的收敛——默认预算上调
（120k tokens / 16 迭代 / 40 步）附实测依据并记录兼容性影响；新增重复调用检测与
答案收束停止策略；[服务回归集](../benchmarks/service-regression-set.md)冻结 20 题，
层级 0 确定性判分 **20/20**（含反向校验），[层级 1 scripted 演练](../benchmarks/m6-level1-scripted.md)
完整公开（含失败形态解读），[M5 基线](phase3-baseline.md)证明三份 benchmark 可从
已提交 trace 逐字节再生。扣分：**层级 2 真实模型批次尚未完成**（正在另一窗口运行），
M6 验收门槛（三轮合计 ≥90%、每轮 ≥80%）未达成，因此不给 4；scripted 数字不得
当作模型能力引用。

### 3.4 客户交付件与服务边界 — 2 / 2（维持）

改善：三个[案例](../case-studies/README.md)按「问题/范围/操作/证据/结论/限制/下一步」
重写，面向客户可读；契约表新增已知限制节（三后端全失败仍 `completed` 的边界与理由）；
`analyze --html` / `export` 能力经 E2E 验证。扣分（维持 2 的原因）：逐例**可下载的
HTML 报告与最小证据包尚未落盘**（M7 验收明确要求）；面向客户的范围/验收/排除项
（[outreach/](../outreach/project-brief.md)）仍是草稿未发布；无客户式审阅记录。
该维度 Upwork 权重 25%，是 Upwork 总分距目标最远的单点。

### 3.5 对外展示与个人贡献说明 — 3 / 3（维持，内容更新）

双语 README 首屏价值主张、Install shortcuts、四组文档地图、作者贡献与第三方引擎
归属、路线图状态已合入；基线指出的「展示文案与旧路线图不一致」已通过
[status.md](../status.md) 与 [ROADMAP](../roadmap/ROADMAP.md) 的进度同步收口。
扣分：README 的独立首读复核正在进行（另一窗口），视频的 Agent 段仍由 scripted
演示 provider 驱动（已如实标注）；Upwork 素材未发布，故不给 4。

### 3.6 独立使用验证 — 1 / 1（维持）

可见记录仍是作者自测、演练与评审。[M10 准备包](m10-acceptance-pack.md)（40 项
验收清单、首次读者指引、客户视角指引、重评模板）已备好，但独立验收未开始——
按「证据缺失不给高分」原则维持 1 分。这不是推断项目没有外部用户，而是没有可引用的
独立复现记录。
