# v1.0.0 发版流程预研（runbook 草案）

**状态：预研文档，不是发版执行记录。** 编写日期：2026-11-17；编写基准：
`claude/m6-level2-verify` 合并成果 `c3586d8`（分支 `claude/release-prep` 的基点）。
本文只准备发版流程：**不发布、不打 tag、不改版本号、不调用模型 API、不发送任何内容。**
是否发版、何时发版、以何种承诺范围发版，由作者决定；本清单不替代
[v1.0.0-release-checklist.md](v1.0.0-release-checklist.md) 的事实核对，两者配合使用
（检查表管「发什么、凭什么」，本文管「按什么顺序、敲哪些命令」）。

项目规则继续适用：生成数字绝不手改（规则 3）；引用必须可回溯（规则 4）；公共契约
显式版本化（规则 5）；发版说明里每一句都要有证据链接。

## 1. 版本号落点

### 1.1 版本住在哪里

版本号只有一处事实来源：[src/dexatlas/__init__.py:11](../../src/dexatlas/__init__.py)
的 `__version__ = "0.2.0"`。`pyproject.toml` 声明 `dynamic = ["version"]`
（[pyproject.toml:6](../../pyproject.toml)），由 hatchling 的版本钩子从
`src/dexatlas/__init__.py` 读取（[pyproject.toml:146-147](../../pyproject.toml)）。
**不要改 pyproject.toml，也不要在任何其他地方再写一份版本号**——历史上两处各写一份
曾导致发布元数据与运行代码不一致，这正是钩子存在的原因。

### 1.2 发版时怎么改

```bash
# 把 0.2.0 改为 1.0.0（Edit 后逐字核对只剩这一处版本字面量）
uv run --no-sync python - <<'EOF'
from pathlib import Path
p = Path("src/dexatlas/__init__.py")
t = p.read_text(encoding="utf-8")
assert '__version__ = "0.2.0"' in t
p.write_text(t.replace('__version__ = "0.2.0"', '__version__ = "1.0.0"'), encoding="utf-8")
EOF
uv run --no-sync python -c "import dexatlas; assert dexatlas.__version__ == '1.0.0'; print(dexatlas.__version__)"
```

发版 commit 里版本号落点共两处：

1. `src/dexatlas/__init__.py:11` — `__version__ = "1.0.0"`；
2. `CHANGELOG.md` — `## [Unreleased]` 改题为 `## [1.0.0] — <发布日期>`，并在文末
   compare 链接块新增：
   `[1.0.0]: https://github.com/gg320324492-lgtm/dexatlas/compare/v0.2.0...v1.0.0`，
   同时把 `[Unreleased]` 的 compare 链接改为 `v1.0.0...HEAD`（见
   [CHANGELOG.md](../../CHANGELOG.md) 文末链接块）。

### 1.3 改完立即核对

```bash
uv run --no-sync dexatlas version          # 必须输出 1.0.0
uv run --no-sync python scripts/check-version-claims.py --base auto
```

`--base auto` 会把「本次要发的版本」识别为待打 tag 的发布而不是不存在的版本
（v0.2.0 预研时该检查 0 findings，见共享笔记 v020-release-prep-complete.md）。
若这里报「v1.0.0 is neither a tag nor the release being prepared」一类错误，
说明 CHANGELOG 或文档里还有把 v1.0.0 当历史事实引用的句子，逐条改为将来时或
「发版后」措辞，直到 0 findings。

## 3. 发版最终 commit 的完整重测与门禁清单（B4）

**顺序不可变**：先改代码/文档 → `ruff format` → 再测量。报告记录源树指纹，格式化
会移动行；先测后格式化会让指纹描述一棵不存在的树，CI 必红。`CLAUDE.md`、`AGENTS.md`
与 `docs/` 不进指纹，改它们不需重测。

### 3.1 完整重测（步骤 3，B4 的正解）

前提：三个后端可用、fixtures 已取（`scripts/fetch-fixtures.sh`）、Pillow 与 ffmpeg
在、全部 git tag 在本机。**不得与其他会话/窗口并发执行**——并发会互相清
`.coverage`，把残缺覆盖率写进报告（本项目已踩过，见共享笔记
concurrent-refresh-pollutes-coverage.md）。

```bash
uv run --no-sync pytest --cov=dexatlas --cov-report=term
uv run --no-sync python scripts/refresh-report-figures.py
```

- [ ] `refresh-report-figures.py` **实际写入了数字**。测量不完整（有 skip、
  缺后端、缺 fixtures）时脚本会拒绝写入并保留旧值——此时不得手改，必须补齐
  前提后重跑。
- [ ] 重跑 `pytest tests/test_docs.py` 与 `check-version-claims.py --base auto`，
  确认全绿（含 source_fingerprint 一致性）。

### 3.2 全门禁清单（步骤 2，逐条命令）

在最终发版 commit 上，以下每条都必须通过：

```bash
# 1. lint + format
uv run --no-sync ruff check .
uv run --no-sync ruff format --check .

# 2. 类型
uv run --no-sync mypy

# 3. 死代码（必须 exit 0）
uv run --no-sync vulture src/ tests/ scripts/ benchmarks/ --min-confidence 80

# 4. 测试套件（读汇总行：failed=0 且 skipped=0，跳过不是通过）
uv run --no-sync pytest -q

# 5. 引用回溯（先 remap 再 check，remap 只在 checker 判定符号离开区间时移动引用）
uv run --no-sync python scripts/remap-citations.py
uv run --no-sync python scripts/check-doc-citations.py

# 6. 版本声明（--base auto 识别本次待发版本）
uv run --no-sync python scripts/check-version-claims.py --base auto

# 7. 文档一致性（60 项）
uv run --no-sync pytest tests/test_docs.py -q

# 8. 报告指纹与数字属于当前树（B4 验收判据；需 3.1 的完整测量在前）
uv run --no-sync pytest tests/test_docs.py::test_execution_report_coverage_figures_describe_the_current_code -q
```

补充核对：

- [ ] `uv run --no-sync dexatlas version` 输出 `1.0.0`。
- [ ] 建议补跑 CI 六 job 的本地对应：Python 3.12 全后端、3.13 无外部后端、
  仅 Apktool、Docker 构建、依赖审计（`pytest` 全量覆盖前三个配置的等价物）。
- [ ] 发版 commit 一旦完成测量，**不得再改 `src/`、`tests/`、`benchmarks/`**；
  改了就回到 3.1 重测。

```bash

# 2) annotated tag（指向步骤 3 之后的最终 commit；与 v0.1.0–v0.2.0 做法一致）
git tag -a v1.0.0 -m "DexAtlas v1.0.0 — The Evidence-First Portfolio Release

Phase 3 portfolio milestone: claims baseline re-verified (M5), frozen 20-question
service regression set with honest level-2 results (M6: retest 49/60 = 81.7%,
below the 90% bar — disclosed, not passed), client-ready deliverables (M7),
public contracts and install/failure rehearsals (M8), bilingual showcase (M9).
Agent answers remain leads, never verified findings."

# 3) 核对 tag 是 annotated 且指向最终 commit
git cat-file -t v1.0.0        # 必须输出 tag
git show v1.0.0 --no-patch    # 能看到注释

# 4) 推送（本机必须走代理；分支名按实际工作分支）
HTTPS_PROXY=http://127.0.0.1:7897 git push origin <工作分支名>
HTTPS_PROXY=http://127.0.0.1:7897 git push origin v1.0.0
```

注意：

- 本机 `git push` 必须 `HTTPS_PROXY=http://127.0.0.1:7897`，两条 push 都要带。
- tag 必须打在**完成了完整重测的最终 commit** 上；tag 后该 commit 不可再改
  （改了就删 tag 重打，并重跑受影响门禁）。
- push 后等 GitHub Actions 在该 commit 上全绿，再进入 GitHub Release 步骤；
  CI 红了先修，不要带病发 Release。
