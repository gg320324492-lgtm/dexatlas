# DexAtlas v1.0.0 — The Evidence-First Portfolio Milestone

---

DexAtlas turns an APK into a picture you can verify — as complete as the installed
backends allow, and the report names what is missing: the manifest and
permissions, a full class/method/field symbol index, decompiled Java source,
call-site and call-graph cross-references, and an evidence trail that records —
for every fact — which tool read it, at which version, from which byte position.

**A conclusion must trace back to the bytes it came from.** Conclusions are graded
`verified` / `lead` / `insufficient`, every fact carries its provenance, and a
backend that fails is reported as a value, not a crash: an APK that defeats the
decompiler still yields a manifest, an index and a report that says which steps
did not run.

This is Phase 3's portfolio-and-delivery milestone: the claims baseline
re-verified against the code (M5), a frozen 20-question service regression set
with honest level-2 results (M6), client-ready deliverables (M7), the public
contract table, workspace-wide `--workspace` and a new exit code (M8), and a
bilingual README showcase (M9).

**The boundary, in one sentence:** this is static, evidence-first analysis, and
the agent inside it is bounded — its answers are leads to verify, never verified
findings.

## Highlights

### This round's delivery

- **Budget efficiency: four fixes plus a row-clipping mechanism.** The agent was
  spending its token budget on reading, not on answering. Four fixes landed
  together: ① `resources` intent adds `KEY_TOOLS`, so a resource question closes
  as soon as the first successful read returns; ② the agent transcript collapses
  repeated data notices (the first keeps its full text, the rest become short
  markers — the MCP responses themselves are unchanged); ②b `search_symbols`
  truncates a string hit's excerpt to one line / 128 bytes, and the tool
  description and the prompt now say "read `limit=20` first, then page"; ③ three
  consecutive reads with no new rows produce a soft hint (not a hard block — a
  legal page-forward that returns new rows clears it). A three-layer row-clipping
  mechanism came with them: a single field is clipped at 4000 characters, a row
  page at 12000 characters, and `total`/`offset` semantics are preserved.
  ([CHANGELOG.md](../../CHANGELOG.md))
- **Two review leftovers closed (M-1 / L-1).** A read-only source review found
  two edges: M-1 — the transcript's clipping notice claimed "the full source has
  been recorded as evidence", but the evidence record stored only the tool and
  the kind, not the text, so the tail of a large clipped class was unreachable;
  L-1 — the row clipper only clipped `symbols`/`declarations`, so the 200-row
  `call_sites` page of `find_callers` bypassed clipping entirely and re-burned
  the budget every round. The fixes carry the source text in the evidence record
  (chunked, with an explicit truncation flag), add optional `offset`/`limit`
  paging to `get_class_source`/`get_method_source` and optional `offset` to
  `find_callers`/`find_callees`, widen the clipped row keys to
  `symbols`/`declarations`/`call_sites`/`callees`, and reword the clipping notice
  to point at the paging continuation instead of claiming the whole text was
  kept. Scoring semantics and the
  [seven scoring rules the scorer will not relax](../architecture/README.md#glossary)
  are unchanged — they are implemented in `benchmarks/model.py::check`. Nine
  red→green regression tests came with it.
- **Release draft and runbook.** The release now has a written change list, a
  step-by-step runbook, a pre-flight checklist and a local dry-run report:
  [v1.0.0-release-commit-draft.md](v1.0.0-release-commit-draft.md),
  [v1.0.0-release-runbook.md](v1.0.0-release-runbook.md),
  [v1.0.0-release-checklist.md](v1.0.0-release-checklist.md) and
  [v1.0.0-dry-run.md](v1.0.0-dry-run.md). None of them executes the release:
  they are the rehearsal, not the act.
- **Documentation sync.** The bilingual READMEs (English and 简体中文), the status
  page, the roadmap and the install guide now say the same thing about M6 and
  about the install extras, and the install guide no longer claims that no APK is
  committed — five first-party sample APKs live under `examples/` with their
  sources, while the third-party fixtures still come from
  `scripts/fetch-fixtures.sh`. ([CHANGELOG.md](../../CHANGELOG.md))

### Milestones in this release

- **M5 — claims baseline.** Every outward claim re-checked against the code and
  the committed traces; the three benchmarks regenerate byte-for-byte from those

- **M6 — frozen service regression set (20 questions).** Level-0 deterministic

## Known limitations

- **M6 level 2 did not reach the acceptance line, and this release does not
  pretend otherwise.** The acceptance bar set for the frozen 20-question set is
  ≥16/20 per round and ≥54/60 (≥90%) over three rounds. The first batch, before
  any of the fixes, scored **24/60 = 40.0%** (45%/40%/35% per round) against that
  bar. The three-round full retest after the execution-layer fixes scored
  **49/60 = 81.7%** (15/20, 16/20, 18/20 per round): r2 and r3 met the per-round
  line, r1 did not, and the three-round total stayed below the ≥90% bar
  (A 21/60, B 21/60; traces 1,182,356 tokens). **Verdict: not met.** The two
  narrow verification rounds over the six known failure surfaces stayed below
  their gate as well — round 2 converted 2/6 (deterministic subset 2/5), round 3
  converted 3/6 (deterministic subset 3/5), against gates of ≥4/6 and ≥3/5. An
  earlier narrow round had converted 4/6 on the rounds it captured, but its run
  stopped at 53 of 54 traces (410,256 tokens, over both the original 400,000
  limit and the amended one), so it is not a verdict and is not counted as one.
  When two consecutive narrow verification rounds missed their gate, the plan's
  stop condition applied — the acceptance plan's option 3, status disclosure —
  and investment stopped for good. The
  [frozen discipline](../architecture/README.md#glossary) holds: the
  system is fixed or the service promise is narrowed and restated — questions
  are never deleted to move a rate.
- **The scope promised for M6 is a bounded, evidence-checkable agent
  walkthrough** over the frozen set — not a claim that the agent meets the ≥90%
  acceptance bar.
- **An agent's answer is a lead, never a verified finding.** The agent inside
  DexAtlas can point at evidence; a human or a rule has to confirm it. That
  separation is the product's core discipline, and it is unchanged here.
- **The level-2 boundary is narrow by construction.** One model
  (MiniMax-M3.1-Flash), temperature 0, first-party small APKs, a closed
  20-question set. The comparison configurations A and B ran under different
  budgets, so the difference between them is not a model-quality claim.
- **A run in which every code backend fails can still record `completed`** with
  a readable manifest, because Apktool may write the manifest before it is
  stopped. The run now answers exit code 6 (`EXIT_NO_INDEX`) instead of 0, and
  the same fact is carried by `errors[]`, `summary.index_complete == false` and
  `run.completeness = "partial"`.
- **The samples under `examples/` include a hand-written obfuscated app.** It
  covers short class/method names — not control-flow obfuscation and not
  commercial packers.
- **What this release does not include:** no native or dynamic analysis
  (`DEXATLAS_GHIDRA_PATH` / `DEXATLAS_RIZIN_PATH` are reserved and unread); no
  plugin ecosystem beyond the tool registry; no published service page; no macOS
  verification (Windows and Linux are the tested platforms); and it is not a
  security audit, a penetration test, a malware verdict or a packer bypass.
- **Independent acceptance has not started.** The M10 acceptance package is
  drafted and self-checked, but no independent reviewer has run it. Nothing in
  this document should be read as a completed acceptance.

## Upgrade notes

Upgrading from **v0.2.0**:

- **New exit code 6 (`EXIT_NO_INDEX`).** `analyze` returns 6 when the run
  finished but no symbol index could be built (every code backend failed; the
  manifest may still be readable). The meanings of 0–5 are unchanged from
  v0.2.0 — exit 5 (`EXIT_TRUNCATED`) already shipped there — but 0's meaning
  narrows: callers that treated 0 as "fully successful" should distinguish the
  two with `exit_code in (0, 6)` or `summary.index_complete`. The report, the
  manifest and `schema_version` are unchanged.
- **`--workspace` / `-w` on every read/write command** (in v0.2.0 only `analyze`
  accepted it). A query command pointed at a missing directory now exits 2
  rather than creating an empty workspace.
- **MCP tools: 10 → 11.** `find_resource_declarations` resolves a resource name
  or value to its declaring files; the ten previous tools are unchanged.
- **Agent default budget raised** to 120,000 tokens / 16 iterations / 120 s,
  plan cap 40 steps (was 20,000 / 8 / 120 s / 12). The four `DEXATLAS_AGENT_*`
  environment overrides are unchanged. The agent JSON report adds a
  `convergence` object and the Markdown report a "How the task converged"
  section — both additive.
- **New: `--html`** (offline single-file HTML report) **and `export`** (minimal
  evidence package). Report `schema_version=3` and evidence-package
  `schema_version=1` are unchanged.
- **Fixed:** the API-served report no longer drops the APK archive facts (hash
  and size); repeated analyses no longer drift the CLI report's `created_at`
  from the stored row; and `androguard:AndroidManifest.xml` provenance resolves
  again.
- **Install:** `uv sync --extra dev --extra analysis --extra mcp --extra demo`
  from the lockfile (v0.2.0 documented `uv pip install -e ".[analysis]"`). See
  [docs/install.md](../install.md).

## 中文摘要

DexAtlas 是一个开源的、证据优先的 Android 静态分析工具：给它一个 APK，它跑三个
分析后端（Apktool 负责 manifest 与 Smali，JADX 负责反编译 Java，Androguard 负责
权威的 DEX 符号图），把结果存进 SQLite 工作区，再渲染成 Markdown / JSON 报告。

项目的核心主张只有一句：**结论必须能回溯到它来自的字节。** 每条结论都分级
（`verified` / `lead` / `insufficient`），每条事实都带出处；后端失败是一个值而不是
一次崩溃——难住反编译器的 APK 依然产出 manifest、索引和一份「哪些步骤没跑」的报告。

本轮交付：预算效率四项修复与行裁剪机制；代码审查遗留的两处边界修复（M-1 裁剪内容
可追溯、L-1 宽页行裁剪补全，带 9 项红→绿回归）；发版草案、runbook、检查表与本地
dry-run 报告；以及 README（英/中）、status、roadmap、install 的文档同步。

**已知限制，照实写出：** M6 层级 2 未达验收线。冻结 20 题服务回归集的验收线是每轮
≥16/20、三轮合计 ≥54/60（≥90%）；首测三轮只有 **24/60 = 40.0%**（逐轮
45%/40%/35%），修复后的三轮完整重测实测 **49/60 = 81.7%**（逐轮 15/20、16/20、
18/20；A 21/60、B 21/60，trace 合计 1,182,356 tokens），r2、r3 达到单轮线，r1 未达，
合计未达 ≥90% 线——判定是「未达标」。两轮窄验证同样未达闸：二轮转通过 2/6（确定性子集
2/5），三轮转通过 3/6（确定性子集 3/5），门槛是 ≥4/6 与 ≥3/5。连续两轮未达后（窄验证
二、三；第一轮运行不完整、**不计为判定**），按验收方案的**方案 3（现状披露）**停止追加
投入：M6 的承诺范围收缩为「有界、证据可核查的 agent 演练」，**agent 的答案始终是待核
线索，不是已验证发现**。M10 独立验收尚未开始。

其余已知限制，与英文版「Known limitations」一一对应：

- **层级 2 的边界本来就窄**：一个模型（MiniMax-M3.1-Flash）、温度 0、一方小样本、
  封闭的 20 题集；对照配置 A 与 B 的预算不同，所以两者的差是执行条件的差，不是模型
  能力的结论。
- **代码后端全部失败的运行仍会记为 `completed`**：Apktool 可能先写下 manifest 才被
  停住。这类运行现在回答退出码 6（`EXIT_NO_INDEX`）而不是 0，同一个事实同时记在
  `errors[]`、`summary.index_complete == false` 与 `run.completeness = "partial"` 上。
- **`examples/` 下的样本含一个手写的混淆应用**：它覆盖的是短类名/短方法名，不是控制流
  混淆，也不是商业加固方案。
- **本次发布不包含**：不做原生/动态分析（`DEXATLAS_GHIDRA_PATH` /
  `DEXATLAS_RIZIN_PATH` 只是预留、不会被读取）；除工具注册表外没有插件生态；没有发布
  服务页；没有 macOS 验证（已测的是 Windows 与 Linux）；它不是安全审计、渗透测试、
  恶意软件定性，也不是脱壳绕过。

验证口径：1620 个测试（1465 快 + 147 集成），完整环境下 1620 passed、0 xfailed、
0 skipped；一方代码覆盖率 93.3%（7117/7631 行）。这两个数字测自 v1.0.0 发版树
（源指纹 `sha256:4e72ac49…`）；指纹覆盖源码树、测试树、`pyproject.toml` 与测量脚本，
不含文档——所以同批的文档改动不影响它。公共契约表活检 49 项
（28 REST + 6 MCP + 15 CLI）；49 是表里的静态条数，任何一次实跑都跑不满它——三后端
齐备那次实跑 48 项、48 项通过、脚本退出码 0。M6 的层级 2 数字全部由脚本从已落盘 trace
重算生成，缺 trace 时脚本拒绝出报告。

从 v0.2.0 升级的要点：新增退出码 6（`EXIT_NO_INDEX`，跑完但无可用代码索引；0–5 的
含义不变，但 0 的外延收窄，自动化脚本请用 `exit_code in (0, 6)` 或
`summary.index_complete` 区分）；`--workspace`/`-w` 覆盖所有读写命令；MCP 工具
10 → 11（新增 `find_resource_declarations`）；agent 默认预算提到 120,000
tokens / 16 迭代 / 120 s / 40 步；新增 `--html` 离线单文件报告与 `export`
最小证据包；安装改为 `uv sync --extra dev --extra analysis --extra mcp --extra demo`。

许可：Apache-2.0。JADX、Apktool、Androguard 以独立进程或库的方式调用，不随本项目
分发。
