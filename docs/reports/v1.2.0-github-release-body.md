# DexAtlas v1.2.0 — Self-contained desktop application and an interface that tells the truth

v1.2.0 ships the whole of Phase 5: a **self-contained desktop application**
(the backend starts with the app — no service to launch by hand), a **stage-level
progress contract** (the backend records its five progression points as facts),
and a batch of fixes under one rule — *the interface must say what actually
happened*: an analysis in progress no longer claims the backends are "not
installed", an analysis that has **finished** no longer claims a version is
"still being probed", a failed analysis is written to the database, the
front-end's time-based simulation is gone, a title in a narrow column no longer
stacks one character per line, and a keyboard user is no longer robbed of the
focus by a button.

Since v1.1.0, main has gained 73 commits merged through 21 reviewed pull
requests.

## What's new

### A desktop application that stands on its own (Phase 5 W1 / W2)

- **The sidecar process**: the Tauri shell starts the existing DexAtlas backend
  (by default `python -m dexatlas.workbench`, forced to `--port 0` so the
  system assigns the port), reads the actual port from the backend's output and
  hands it to the front end; when the sidecar exits or crashes the page says
  so instead of inventing data; the settings page can change the backend
  command and restart it.
- **Killing the host leaves no orphan backend**: a Windows **job object** is the
  safety net — the backend is created suspended, put in the job, and resumed,
  so the processes it spawns inherit the job identity; when the host dies the
  system closes the job handle and the whole process tree goes with it. **That
  layer is now a CI gate** (`cargo test --lib`, Windows only) — the 24 Rust
  tests had no gate running them at all.
- **A stage-level progress contract**: the pipeline records a stage event at
  each of its five progression points — `inspect` → `parse-apktool` →
  `index-androguard` → `decompile-jadx` → `publish` — behind a new read-only
  endpoint `GET /api/projects/{id}/runs/{run_id}/stages` (same shape over REST
  and workbench). The existing run object's field set is unchanged: purely
  additive.

### An interface that tells the truth

- **The front-end's time simulation is deleted** (PR #23): with no backend
  fact to read, the page says the state is unknown instead of drawing a
  progress bar that looks like a fact.
- **A failed analysis is written to the database** (PR #26): the pipeline
  computed `FAILED` but only called `publish_run` on `COMPLETED` — the failure
  was never stored, the project row stayed `running`, and the interface still
  said "analysing" **4 minutes 44 seconds** after the analysis had ended.
- **An analysis in progress no longer claims the backends are "not installed"**
  (PR #30): that run's `tool_versions` were not written until the version
  probing had finished, and the front end read "no such key" and "the value is
  null" as the same thing.
- **A finished analysis no longer claims a version is "still being probed"**
  (PR #33): a `null` version means one of two quite different things — "not
  probed yet" or "not installed" — and the run's record cannot tell them
  apart. The machine's own list (`GET /api/backends`) and the run's record are
  now read together, so each statement rests on the fact that supports it.
- **The stage slots correspond one to one with the backend's progression
  points** (PR #32): the "parse" slot is split into "parse" and "decompile",
  and the "evidence" slot is gone (the evidence is still produced; it just no
  longer occupies a slot for which the backend has no progression point). What
  a slot shows **is** what the backend reported, and the badge no longer has
  to explain which slot was an inference.
- **A title in a narrow column no longer stacks one character per line**
  (PR #31).
- **A button that becomes unavailable does not take the focus** (PR #33): the
  cancel button uses `aria-disabled`, so the keyboard user is not thrown back
  to the top of the page the moment the cancellation starts.

### Acceptance and verification on real hardware

- **The packaged executable with the complete backend configuration**: with
  JADX + Apktool + Androguard all present it produces 12 evidence records and
  `complete: true`; the MSI path installs (`msiexec /i … /passive`, exit code
  0) and the installed application starts and analyses. (`/qn` does **not**
  install: in silent mode Windows Installer does not elevate credentials — a
  mechanism limitation, not a defect of the package.)
- **Both the failure and the cancellation timelines walked on real hardware**:
  the cancellation path really exists (red cancel button → confirmation →
  `POST /cancel` → the pipeline stops at its next checkpoint → the run is
  recorded `cancelled`, the project `failed`, and **nothing is published**).
  Cancelling during **other** stages (during indexing, during decompiling)
  was walked as well, each time deciding "the target stage is running" from
  the backend's own stage-event endpoint rather than by watching the screen.
- **An inventory of what is still open**: the unfinished items scattered across
  the acceptance report, the walkthrough, the machine-verification report, the
  status page and the operations checklist are collected in one place and
  sorted into four classes.

## Verification

The suite is **1887** tests (1738 fast + 149 integration), **1886 passed, 1
skipped, 0 xfailed**, with **93.4 %** first-party coverage (7485/8018 lines),
measured by `scripts/refresh-report-figures.py` against the released tree in a
complete environment (backend paths, fixtures, Pillow, ffmpeg; nothing hidden
behind skips — the one skip is the POSIX launcher test, which is skipped by
design on Windows). ruff lint + format, `mypy` strict, `vulture`, the citation
checker, the version-claim checker, the release-number checker and the
social-preview check all pass. `npm run build` is clean, vitest is **70**
green, and the Tauri release form was exercised end to end on real hardware
(upload → evidence → export).

## What this release does not claim

- The desktop application's first acceptance platform is Windows; macOS and
  Linux are unverified.
- No app-store distribution, update service or signing certificate is part of
  this release; the installers are local build artifacts, and **this release
  ships without installers**.
- Real third-party APKs (hardened, large multi-dex) and the MSI's
  upgrade / uninstall / repair paths are **unmeasured** — they need external
  samples or another machine, and are recorded in the open-items inventory
  (class D).
- The **Esc** key on the cancellation dialog is **unverified**: the dialog is
  not a separate window (WebView2 draws it inside its own window), so there
  is no window to hand the key to, and the debugging protocol only offers
  "answer on the user's behalf". What could be checked is the browser's own
  two answers: "cancel" → the analysis keeps running, "confirm" → the cancel
  request is sent.
- The desktop application calls the existing analysis core over local HTTP; it
  adds no new analysis capability.
