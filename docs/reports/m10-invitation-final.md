### 四、执行路径

完整分步命令、每步预期输出与记录格式，以
[读者验收包 §3](m10-reader-package.md) 为准；此处是路径概览：

1. **clone 并检出固定 commit**：按[读者验收包 §3.1](m10-reader-package.md)
   执行 `git clone` 与 `git checkout v1.0.0`，`git status` 应为干净。
2. **环境准备**：按[读者验收包 §3.2](m10-reader-package.md) 执行
   `uv sync --extra dev --extra analysis --extra mcp --extra demo`
   （或 Docker 路线），运行 `uv run dexatlas backends` 确认后端状态。
   没有外部后端不要停，这本身是验收项 A6 / G2 的降级场景。
3. **首次分析**：按[读者验收包 §3.3](m10-reader-package.md) 对
   `examples/demo-app/demo.apk` 执行 `uv run dexatlas analyze`，
   记录实际计数（预期 5 classes / 8 methods / 23 call sites /
   21 call edges / 1 resource string；不同先核对后端是否齐全）。
4. **案例与证据核查**：按[读者验收包 §3.4–3.7](m10-reader-package.md)
   执行 manifest / search / source / xrefs、三格式报告导出、证据包导出与
   校验，并任选 3 条 evidence 记录核对工具、版本、locator、level 四字段：
   - `tool` 与 `version` 抄这条 evidence 记录自己写的值，不用另行查证；
   - `locator` 要能在你导出的证据包里解析到对应字节；
   - `level` 按[读者验收包 §3.4](m10-reader-package.md) 的三级语义读：
     `verified`＝确定性工具产出且引用可解析，`lead`＝待核线索不是结论，
     `insufficient`＝证据不足。
   - 四字段里只要有一项与你抽到的证据对不上（尤其把 `lead` 当成结论用），
     就写进客户视角审阅备忘——这是验收项 C3（★ 阻断项）的判定依据。
5. **源码评审（如您承担该角色）**：按
   [验收准备包 §6 源码评审清单](m10-acceptance-pack.md)逐里程碑核对
   M5–M9 的证据入口与核对动作；没有执行的动作记「未验证」。
6. **逐项判定**：对照
   [验收准备包 §2 的 40 项检查表](m10-acceptance-pack.md)逐项给出
   三态判定；每项写明命令、退出码、关键输出、耗时与路径。
7. **打分**：按[验收准备包 §5 的空白评分表](m10-acceptance-pack.md)
   给 GitHub / Upwork 两套权重分别打分，每项附扣分理由；两个平台
   **分别** ≥90% 才算达到评分目标，平均分不能替代，且分数不能抵消
   阻断缺陷。
8. **填写并交回记录**：把上述过程填入
   [验收记录模板](m10-review-record-template.md)，按
   [读者验收包 §5.3 的提交格式](m10-reader-package.md)交回发起人。

### 五、40 项清单与 19 项阻断项

- [验收准备包 §2](m10-acceptance-pack.md) 的检查表共 **40 项**，分 7 组：
  A 环境与首次分析、B 交付案例、C 证据与可追溯性、D 交付件与数据隔离、
  E 服务回归集结果解释、F 公共契约核对、G 故障恢复与诚实边界。
- 其中 **19 项是标 ★ 的一票否决阻断项**：A2、A4、A6、B1、C1、C2、C3、
  C5、C6、D1、D2、D3、E2、E3、F1、F5、G2、G3、G5
  （判定标准见[准备包 §2.8](m10-acceptance-pack.md)）。
  这些编号是判定表里的**验收项编号**（如 B1 = 「按案例从 analyze 走到 xrefs
  全程完成」），与「M6 的 B1 验收线」（发版阻断项）不是一回事。
- **任何一个阻断项「不通过」，M10 即不通过**；其他项的高分不能抵消。
- 非阻断项不通过时，请写清影响范围、是否有替代证据、是否接受遗留。
- 每项判定标准都写在检查表内，请按标准判，不按印象判；没有执行的项
  记「未验证」。

**请不要把作者侧的自查当成验收结论。** 作者另有一套自动化自查脚本
（`scripts/m10_selfcheck.py`），当前快照是「43 条自动化判定通过、40 项留人工」
（见[作者侧自查](m10-selfcheck.md)）。那是**另一个分母**：43 是脚本自己能回答的
检查条数，40 是留给读者实做的那一组，与您要判的 40 项**不是同一组东西**。
自查全绿**不表示**这 40 项中有任何一项被判通过——M10 的判定只来自您。
